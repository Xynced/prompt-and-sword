# План: Бой — приёмы оружия

Статус: в работе · команда: `continue weapon-moves plan`

## Проблематика

Запрос пользователя (2026-08-15): у каждого героя сейчас одна-две атаки плюс
способность; нужен **реальный выбор действий — не менее 5 на героя**, причём
внутри одного класса варианты пересекаются **не больше чем на 2 действия**.

Что сломано в текущей модели:

- Виды атак универсальны: слабый (1 AP ×0.45) / полный (2 AP ×1.0) /
  отчаянный (2 AP ×1.5, открывает) одинаковы у всех — от кинжалов до посоха.
  Оружие различается только цифрами и мягкой аффинностью, которую почти не
  видно (±1.2 очка скоринга против премии слова 2.5).
- Из-за этого возможна доминация внутри арсенала: у Яра меч 7 и молот 8 при
  равной дальности — молот строго лучше в полном ударе, меч оправдан лишь
  невидимой аффинностью слабого. Пользователь прямо просит такое исключить.
- Аудит плана words подтверждает: манеры удара как универсальные слова слабы
  («наверняка» −1…−4, «отчаянно» — ниша не найдена ни одной парой). Слово
  «бить отчаянно» бессмысленно щитоносцу и должно быть родным секироносцу —
  но пока отчаянный удар у всех одинаков, нише неоткуда взяться.

Идея пользователя: **виды атак — свойство вооружения, а не персонажа**.
Топор даёт тяжёлые удары, делающие тебя уязвимым; кинжал — быстрые слабые
уколы с бонусом при атаке в окружении; и т.д.

Трудности: та же, что у плана classes, — не раздуть боёвку (глубина должна
жить в слое принципов); words-план активно меряет манеры и стойки — база
замеров сдвинется; линзы тянутся к видам действий (`actionBias`), UI и
карточки показывают действия по именам.

## Проработка

### Рамка: приём — атака, определённая оружием

**Приём** (`WeaponMove`) — именованная атака конкретного оружия:

```ts
interface WeaponMove {
  id: string;        // стабильный id для тестов и UI
  name: string;      // «сплеча», «град уколов», «пролом»
  slot: 'weakAttack' | 'attack' | 'selflessAttack'; // темп: быстрый 1 AP / полный 2 AP / рисковый 2 AP
  mult: number;      // × dmg оружия × DMG_SCALE
  ap?: 1 | 2 | 3;    // цена, если отличается от цены темпа (замах с оттяжкой — 3)
  range?: number;    // дальность приёма, если отличается от range оружия
  // райдеры — до одного-двух на приём, все на готовых каналах:
  expose?: boolean;  // открывает бьющего (канал exposed)
  pierce?: number;   // цели остаётся эта доля митигации; рипост не ловится (канал HARD_PIERCE)
  push?: boolean;    // цель сдвигается на 1 от бьющего (канал толчка; некуда — просто урон)
  gang?: number;     // +gang к mult за каждого союзника вплотную к цели сверх первого
  stepBack?: boolean;// после удара шаг на 1 от цели, если клетка свободна
  twin?: boolean;    // урон делится по двум разным целям в дальности (два слабых расчёта)
}
// WeaponSpec.moves?: WeaponMove[] — у оружия без кита действует дефолт-тройка
```

Ключевые решения:

- **Слоты-темпы остаются каркасом.** `ActionKind` не меняется: приём занимает
  один из трёх темпов (быстрый/полный/рисковый). Это сохраняет работу слов
  («бить часто» → приёмы быстрого темпа, «отчаянно» → рискового), стоек
  (`stance.often` усиливает быстрые приёмы, `hard` даёт пирс полным — при
  врождённом пирсе берётся максимум, не сумма), линзовых тяг
  (`actionBias.weakAttack` = тяга к быстрому темпу) и всего скоринга.
  «Убрать типы атак» происходит на поверхности: игрок видит имена приёмов
  («Рык: сплеча по волку»), а не «слабый/полный удар».
- **Оружие может не иметь темпа.** У двуручной секиры и арбалета нет быстрого
  приёма — «бить часто» с ними молчит по построению (жёстче и честнее нынешней
  мягкой аффинности). Поле `affinity` при переезде кита изымается: вкус оружия
  выражает сам состав приёмов, а не невидимый бонус.
- **Дефолт-тройка** для оружий без кита: «тычок»/«удар»/«размен» — ровно
  сегодняшние числа. Все враги и «голые» юниты тестов проходят через неё —
  старые фикстуры обязаны выжить (урок планов aoe/classes). Своих китов врагам
  в этом плане не даём (кроме, возможно, босса — решить на перемере).
- **Анти-доминация — правило кита:** два приёма одного темпа в арсенале
  одного героя обязаны различаться райдером или дальностью, а не только
  числом. Молот Яра не «меч+1», а пролом (пирс укрытий и щитов); меч — лучший
  быстрый укол; копьё — единственное с дальностью 2.
- **Райдеров ровно шесть** (expose, pierce, push, gang, stepBack, twin), все
  на существующих каналах; потолок жёсткий — новые райдеры только через
  words-нишу и замер. Это главная защита от раздувания боёвки.

### Что считается «действием» для нормы «≥5, пересечение ≤2»

Считаются: приёмы оружия + классовые активы + площадные формы + именные
защитные фишки (щит Грома −40%, дешёвая глухая оборона Скалы). Не считаются:
общие для всех move/cover/swap/wait и пассивы (они не выбор). Пересечение —
приёмы с одинаковым профилем (слот+райдер) или общий актив.

### Слова и стойки (сверить с планом words)

- «бить часто» / «наверняка» / «отчаянно» — остаются, семантика прежняя
  (предпочтение темпа + стойка), но их ценность теперь зависит от арсенала:
  «отчаянно» впервые получает нишу (секиры, арбалет в упор — множители выше
  общих 1.5), «часто» молчит у Рыка и Радима. Это прямой ответ на хвост
  words-плана «отчаянно без ниши».
- Пирс «наверняка» и врождённый пирс приёма не складываются — max.
- Новых слов ноль. Райдеры push/gang/stepBack/twin гейтов не требуют — это
  свойства удара, скоринг оценивает их через готовые премии (толчок в шипы,
  фланг, отход из ZoC).

### Скоринг и исполнение

- Кандидаты атак: цикл «по оружиям × по приёмам» вместо «по оружиям × три
  манеры»; `Candidate.move` — индекс приёма. `AP_COST`/`ATTACK_MULT` для атак
  читаются из приёма (`apCostFor`/`attackMultFor` получают приём).
- Исполнение в battle.ts: райдеры переиспользуют готовые ветки (push — код
  толчка, stepBack — шаг, expose — код отчаянного, gang/pierce — множители в
  формуле урона, twin — два вызова формулы).
- `WEAPON_AFFINITY_BONUS` изымается вместе с полем affinity (см. выше);
  `weakMult` Юны переезжает в её приём «шквал».
- UI/карточки/разведка: `describeWeapon` перечисляет приёмы с числами; лог
  боя пишет имя приёма («Тесса: град уколов по крысе»).

### Риски

- Раздувание боёвки — потолок 6 райдеров, новые только через words-нишу.
- Сдвиг базы замеров words-аудита (стойки и манеры меняют смысл) — перемер
  обязателен, старые числа несравнимы; координация с планом words (в работе).
- Линзы: тяги `actionBias` по темпам сохраняются, но горячка с Рыком (нет
  быстрого) и трус с арбалетом требуют смоуков — тяга к пустому темпу не
  должна давать нулевой ход.
- Бот автобаланса не знает приёмов — но ему и не надо: кандидаты сами
  предлагают лучшее; кривую держать в допуске ±10.
