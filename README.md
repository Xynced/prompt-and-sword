# Prompt & Sword — фазы 0–4

Роуглайк-автобатлер, где билд — это текст. Полная проработка: [prompt_and_sword_plan.md](prompt_and_sword_plan.md).

## Запуск

```bash
pnpm install
pnpm test          # юнит-тесты (включая критерии Ворот A)
pnpm sim gateA     # статистика: 5 наборов IR × 50 сидов + тест дивергенции
pnpm sim run rush 1  # подробный лог одного боя (набор, seed)
pnpm sim demo-run 1  # забег целиком по карте: карточки, бои, события, босс
pnpm dev             # веб-UI: играбельный забег (http://localhost:5173, ?seed=N)

# Фаза 3 — LLM-компилятор (нужен ключ; без него всё работает через конструктор):
pnpm sim compile "Прикрывай Лию, а если врагов больше — отступай"  # текст → IR → карточка
pnpm sim corpus      # прогон corpus/*.txt: % скомпилированных / с неуверенностью / дифф с намерением
```

Провайдер компилятора настраивается через env (по умолчанию Anthropic / `claude-sonnet-5`):

```bash
# Отладка на DeepSeek (Anthropic-совместимый эндпоинт):
export COMPILER_API_KEY=sk-...            # ключ DeepSeek
export COMPILER_BASE_URL=https://api.deepseek.com/anthropic
export COMPILER_MODEL=deepseek-chat
# Финал: убрать эти переменные и задать ANTHROPIC_API_KEY — вернётся claude-sonnet-5.
```

Подойдёт любой Anthropic-совместимый эндпоинт (DeepSeek, LiteLLM-шлюз и т.п.).
Идентификатор модели входит в ключ кэша — смена провайдера не отдаёт чужие
закэшированные компиляции. Валидация выхода (схема из открытого словаря +
программная проверка + гейт `compilePhrase`) не зависит от провайдера: слабая
модель может ошибаться чаще, но невалидное правило не выдаст. Целевые ≥85%
Ворот C меряются на финальной модели.

Наборы для `run`: `rush`, `focus-leader`, `turtle`, `guard-mage`, `kite`, `rush-variant`.

## Что реализовано

- **IR** ([src/ir.ts](src/ir.ts)) — 12 концептов MVP: условия (hp ниже X, врагов больше, союзник в опасности), селекторы (ближайший, слабейший, лидер), действия (атаковать, защищать, держать позицию, отступать), пространство (рядом с, позади). Плюс 9 концептов позднего словаря (фаза 4): условия «бой затянулся» и «мы быстрее», селекторы «самый опасный» и «кто атаковал меня», действия **приманка**, **размен**, **прикрывать отход**, пространство **фланг** и **вне линии огня** — стратегии, невыразимые ранним словарём.
- **Линзы характеров** ([src/lens.ts](src/lens.ts)) — детерминированные трансформации IR, 10 в пуле: трус (прикрывать → стоять позади, штраф рискованным правилам, бегство при hp<30%), фанатик (отступление → атака, игнор ZoC), буквалист (нет правила → глухая оборона), мститель (бьёт обидчика), дуэлянт (слабых не добивает, в спину не бьёт), славолюб (цель — только вожак), наседка (усиленная защита своих), параноик (вне линии огня), горячка (не стоит на месте), позёр (фланги и приманка). Каждый герой при генерации забега получает 1–3 случайные линзы (детерминировано сидом); линзы применяются по порядку, их искажения складываются.
- **Боевое ядро** ([src/battle.ts](src/battle.ts), [src/grid.ts](src/grid.ts)) — сетка 8×8, инициатива по скорости, фланг/LoS/ZoC, seeded RNG (mulberry32), event-sourced лог.
- **Utility-скоринг** ([src/scoring.ts](src/scoring.ts)) — инстинкты (класс/характер) + веса сработавших правил; топ-3 фактора каждого решения пишутся в лог.
- **Конструктор принципов** ([src/constructor.ts](src/constructor.ts), [src/vocab.ts](src/vocab.ts)) — фразы из чипсов словаря → IR без LLM; закрытый концепт — ошибка компиляции, не догадка.
- **Карточки «как понял»** ([src/cards.ts](src/cards.ts)) — шаблонный обратный перевод IR после линзы; искажения помечены ⚠ и видны до боя.
- **Спарринг** ([src/sparring.ts](src/sparring.ts)) — тот же seed, переписанные принципы; дифф: исход, раунды, потери, раунд расхождения.
- **Забег по карте** ([src/run.ts](src/run.ts)) — ветвящаяся карта из 15 узлов (à la Slay the Spire): урок / бои / элитки / события / привал / скрипторий / босс; игрок выбирает путь. HP переносится между боями (перевязка +25% после победы, привал лечит 60% недостающего), пермасмерть. События: книжник (концепт задаром), тайник (+1 слот), наёмник — занимает место погибшего с **другим набором линз**, прежние принципы читаются иначе. Всё детерминировано сидом забега.
- **Онбординг** — первый узел «урок»: по симу (100 сидов, случайные линзы) дефолтные принципы проигрывают ~60% сидов, универсальный кайт выигрывает ~52% — выигрышная формулировка зависит от выпавших линз, урок учит читать карточки «как понял». Поражение в уроке ничего не стоит (забег не кончается, раны не переносятся) — UI сам предлагает переписать приказ и переиграть с теми же костями.
- **Поздние враги** ([src/foes.ts](src/foes.ts)) — шаман (держится за спинами), берсерк (размен), охотник (снимает самых опасных), Вождь орды (босс; свита подобрана симом: наивный «фокусь вожака» проигрывает, снятие свиты под заслоном — выигрывает). У урока, элиток и босса перед боем видна **разведка** — принципы врагов после линзы (`foeIntel`): бой — задача на контр-формулировку.
- **LLM-компилятор** ([src/compiler/](src/compiler)) — свободный текст → те же `PhraseDraft`/IR, что и у конструктора (strict tool use; модель настраивается, по умолчанию `claude-sonnet-5`). Строгая JSON-схема строится из **открытого** словаря — закрытый концепт невыразим на уровне схемы; поверх — программная валидация и финальный гейт тем же `compilePhrase`. Неоднозначность → простейший маппинг + заметка в `uncertainty` (⚠ на карточке до боя). Кэш по полному ключу текст+словарь+характер: `.cache/compiler.json` (CLI) / localStorage (UI). LLM в бою не участвует; тесты компилятора — на моках.

Инвариант: тот же seed + те же принципы = тот же бой (тест на побайтовое совпадение лога).

## Ворота A — статус

Прогон `pnpm sim gateA` (50 сидов):

| Критерий | Результат |
|---|---|
| Разные наборы правил → статистически разные исходы | winrate 18–92%, длительность 5.5–6.7 раундов, centroid.x 0.55–1.31 |
| Смена 1 правила меняет ход боя в ≥60% сидов | **98%** (исход переворачивается в 54%) |
| Лог решений читается | `pnpm sim run <set> <seed>` — у каждого решения топ-3 фактора с именами правил |

Критерии закодированы в [test/gate-a.test.ts](test/gate-a.test.ts).

## Веб-UI (фазы 2 и 4)

[src/ui/main.ts](src/ui/main.ts) — чистый DOM + Vite, без фреймворка, стилистика
«полевой дневник тактика» (пергамент, чернила, сургуч). Экран карты (SVG-граф
узлов, клик по достижимому узлу — переход), панель узла (бой с разведкой /
скрипторий / событие / привал), конструктор фраз с живыми карточками «как понял»,
полосы hp героев между боями. Экран боя: сетка 8×8, автопрокрутка, лог решений
с факторами, «Переиграть с теми же костями».

Свободный текст в UI: задай в `.env` ключ `VITE_COMPILER_API_KEY` (совместимо и
`VITE_ANTHROPIC_API_KEY`), опционально `VITE_COMPILER_MODEL` и
`VITE_COMPILER_BASE_URL` (напр. DeepSeek для отладки) — у каждого героя появится
тоггл «✎ текстом» рядом с конструктором. Без ключа UI работает только на
конструкторе (оффлайн-режим). Ключ уходит в браузер — только для локальной
разработки.

## Ворота B — что осталось

Игра играбельна end-to-end. Осталось: 10 своих забегов + 3 внешних тестера,
наблюдение за спаррингом и считываемостью характеров (см. критерии в плане).

## Ворота C — подготовка

Корпус формулировок — [corpus/sample.txt](corpus/sample.txt) (формат: `текст`
или `текст => ожидаемое понимание`); реальные 100 формулировок собираются с
плейтестеров на Воротах B. `pnpm sim corpus` печатает отчёт: % скомпилированных,
% с неуверенностью, совпадение с намерением. Критерий «инъекции отбиваются
схемой» закодирован в [test/compiler.test.ts](test/compiler.test.ts).

## Фаза 4 — заметки по балансу

Урок и босс подогнаны прогонами headless-сима (см. комментарии в
[src/run.ts](src/run.ts)); ключевое наблюдение — 4-й враг в бою против партии из
трёх делает бой почти нерешаемым (экономика действий). Баланс полного забега
(смертность в середине, кривая сложности элиток) — фаза 5, автобаланс прогонами.

## Сознательно отложено (по плану)

- Способности героев (рывок/залп/лечение) — не нужны для Ворот A.
- Террейн/препятствия — LoS блокируется только юнитами; концепт «узкое место»
  отложен вместе с террейном.
- «Как понял» голосом персонажа (LLM-обратный перевод) — сейчас шаблоны + заметки
  неуверенности; флейвор после Ворот C.
- Селектор «помеченный» и командный фокус-огонь — требуют party-scope правил
  (не в MVP).
