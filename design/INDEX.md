Пакет задач для дизайн-агента (Claude Design). Каждый файл `NN-*.md` —
самодостаточный бриф: его можно отдать целиком, не пересказывая контекст.
Этот файл — общий контекст, дизайн-система и правила, действующие во всех
задачах.

Экран боя в этот пакет **не входит** — он остаётся как есть.

## Что за игра

Роуглайк-автобатлер, где билд — это текст. Игрок не управляет героями в бою:
он **пишет им принципы** («если ранен — отступать», «атаковать ближайшего»), и
эти принципы компилируются в правила **до боя**. Бой — детерминированная
арифметика на сиде: те же кости + те же принципы = тот же исход, всегда.

Соль игры в зазоре между «что я написал» и «как меня поняли»: у каждого героя
скрытый характер (линза), который читает приказ по-своему — трус превращает
«прикрывать» в «стоять позади», фанатик выбрасывает осторожные оговорки.
Игрок узнаёт характер по поведению в бою, а не из карточки.

Заголовок и полная проработка — `prompt_and_sword_plan.md` в корне.

## Что уже работает (и как посмотреть)

```bash
pnpm dev
```

Открывается разворот кодекса: слева карта похода и панель текущего узла,
справа «наш отряд»: карточка на героя — hp, быстрый доступ в лист и полоска
действующего набора. Клик по полоске — окно конструктора; клик по имени
героя — лист героя; «⚔ выступить» — экран боя.

Код UI: `src/ui/main.ts` (весь UI одним файлом, чистый DOM-строками, без
фреймворка) и `src/ui/style.css`. Карта модулей игры — `src/INDEX.md`.

## Дизайн-система как она есть

Метафора — «полевой дневник тактика», разворот рукописной книги.

Токены (`src/ui/style.css`, `:root`):

```
--ink      #1f1b16   основной текст
--red      #9c3b28   акцент, рукописные пометки, активные элементы
--red-hover#c04d33
--paper-l  #f0e8d5   левая страница
--paper-r  #f4ecd9   правая страница
--modal    #f6efdd   оверлеи
--cover    #e3d8bf   переплёт
--ink-30 / --ink-45 / --ink-55   полупрозрачный текст
--serif  'EB Garamond'  основной текст
--hand   'Caveat'       рукописные пометки — «как понял», флейвор
--mono   'Courier Prime' служебные подписи, цифры, статы
```

Три гарнитуры несут смысл, а не украшают: **serif** — то, что напечатано в
дневнике; **hand** — то, что герой/игрок дописал от руки (реплики «как понял»,
подсказки); **mono** — сухие числа и служебное (статы, теги, тумблеры).

Холст: `.book` — фиксированные **960×640 px**, отцентрован и масштабируется
целиком под окно (`computeFit()` в `src/ui/main.ts`). Отсюда главная беда —
служебная типографика ужата до 8–10.5 px, см. задачу 1.

## Правила, которые нельзя нарушать в макетах

1. **Характеры героев скрыты.** Линза (`трус`, `фанатик`, …) показывается
   только в debug-режиме (`lensTagHtml`). В обычной игре игрок её угадывает.
   Макет не должен «нечаянно» вывести характер в статблок.
2. **Принципы врага видны только при разведке** — на узлах «урок», «элита»,
   «босс» (`intelVisible` в `src/run.ts`). На обычном бою — «прочтёшь по ходу».
3. **Реплики «как понял» — единственный канал искажения.** Это рукописная
   цитата в кавычках, красным, шрифтом hand, с «⚠ понял по-своему» там, где
   компилятор не уверен. Формат менять можно, роль — нет.
4. **Бой не трогаем.** Экран боя, его анимации и раскладка остаются.
5. **Русский язык**, строчные буквы в служебных подписях — часть тона.

## Формат сдачи (для каждой задачи)

- **Один самодостаточный HTML-файл**: разметка + `<style>` внутри, без
  фреймворков, без сборки, без внешних картинок и иконочных шрифтов (все
  глифы — типографика: `α × ✕ ? ~ § Ω ⚔ ◎ ⚑`). Шрифты — те же три с Google
  Fonts. Палитра — только из токенов выше; если нужен новый токен, он
  объявляется в `:root` и перечисляется в записке.
- **Все состояния экрана на одной странице**, друг под другом, подписанные
  (не «идеальный кадр», а рабочий набор: пусто / заполнено / ошибка / debug).
- **Записка на 10–15 строк**: что поменялось и зачем; какие элементы уехали;
  какие данные макет требует, а в модели их **нет** (см. секцию «данных нет»
  в каждой задаче) — это список на реализацию, не на выдумывание.
- Верстать под холст 960×640 (или под тот, что выберем в задаче 1) — макет
  должен помещаться без скролла страницы; внутренние области могут скроллиться.

## Открытые продуктовые вопросы

Ответы нужны до задач 3–5; в брифах указаны рекомендованные дефолты, чтобы
дизайн не стоял.

1. **«Фокус» — имя занято.** В конструкторе приказов «фокус» уже означает
   третий уровень важности фразы (вес 3, план `nerve`). Если ресурс похода
   тоже назвать «фокус», в одном экране будет два разных фокуса.
   → Рекомендация: развести названия (ресурс — «сосредоточенность»/«воля», либо
   уровень важности переименовать в «главное»). Решение — за автором.
2. **Что покупают разведка и фокус.** Ресурсов в модели нет ни одного
   (`RunState` в `src/run.ts` хранит только словарь, героев, метку, расстановку
   и трофей). Дизайну нужно знать: копятся или тратятся за узел, чем
   пополняются, что дают. → Рекомендация на время макета: разведка —
   заряды «посмотреть карточку врага до боя», фокус — заряды на пометку
   фокус-огня / уровень важности приказа.
3. **Артефакты.** Механики нет. Сколько слотов на полке, есть ли редкость,
   можно ли снимать. → Рекомендация: полка на 6 слотов, пустые видны как
   пунктирные гнёзда — место обещано заранее.
4. **Общее поле приказов на отряд** (задача 5): это отдельный слой «приказ
   всем» поверх личных, или текст, который раздаётся по героям и занимает их
   слоты памяти? → Рекомендация: отдельный слой, свой лимит, читается каждым
   героем через его характер (иначе слоты кончатся мгновенно).
5. **Предполагаемые черты** (задача 4): игрок просто помечает догадку для себя,
   или за верную догадку что-то даётся? → Рекомендация для макета: заметка для
   себя, без механики.
